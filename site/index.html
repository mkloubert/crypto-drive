Your files,

Still just a folder.

crypto-drive shows an encrypted folder as a normal drive. You work in the drive like in any folder. On disk, every file content and every name is encrypted, so the folder is safe to put into Dropbox, Nextcloud, Syncthing, OneDrive or iCloud Drive.

    01 — Features

    Built for the cloud folder

    Per-file encryption, files that never change behind your back, and a format that keeps sync clients happy.

    [ contents + names ]

    Everything is encrypted

    File contents in 64 KiB chunks with AES-256-GCM. File and directory names with AES-256-SIV. From the outside you only see random names.

    [ sync safe ]

    Made for sync clients

    Every file is one real file. Control files never change after they are created, so Dropbox, Nextcloud or Syncthing only upload what you changed.

    [ conflicts ]

    Conflict copies stay visible

    When a sync client makes a conflict copy, the drive shows it as name (conflict 1).txt. Rename it to resolve it.

    [ integrity ]

    Tampering gives an error

    Bit flips, swapped or cut chunks and swapped files are detected on read. Content is bound to its name, so you never get wrong plaintext.

    [ key file ]

    Key file outside the vault

    The master key is wrapped with your password (Argon2id) and stored in ~/.crypto-drive/keys. Someone with only the vault cannot attack your password offline.

    [ rotation ]

    Key rotation & recovery

    rotate-key re-encrypts the whole vault with a new master key and continues after a crash. A 55-character recovery key brings back a lost key file.

    [ padding ]

    Optional size padding

    init --pad-sizes rounds every file up to a size stage with random bytes. Outsiders see the stage, not the exact size.

    [ post-quantum ]

    Symmetric only

    Only symmetric primitives with 256-bit keys. Grover's algorithm leaves about 128 bits of security. No asymmetric crypto to break.

    [ hardened ]

    Careful with secrets

    Keys are wiped from memory and locked in RAM. No core dumps, no debugger attach. Logs never show clear names unless you ask with --debug.

    02 — How it works

    Two folders, one truth

    The drive is a FUSE file system. Every operation in the drive is mapped at once to the encrypted vault folder. Nothing is stored in a big container file.

    1. 01

      You use the drive

      Finder, your editor, cp or rsync work on ~/drive as on any folder.

    2. 02

      crypto-drive encrypts

      Each name gets a random entry id and is encrypted with the id of its parent directory. Content is sealed chunk by chunk with a key per file.

    3. 03

      Your cloud syncs the vault

      The sync client only ever sees ~/vault: random names, encrypted bytes, small control files that never change.

    Vault layout

    vault/
├── .cd-vault          marker (vault id, epoch, tag)
├── 55eQBYxGPA4P…Va0    encrypted file
├── _YGZng9Ozs58…2nY/   encrypted directory
│   ├── .cd-dir        directory id, never changes
│   └── W_wtktFV-a_R…qaL
└── .cd-cdl<hash>/     entry with a very long name
    ├── .cd-name
    └── .cd-content

    One file on disk

    header
    chunk 0
    chunk 1
    …
    last
    • header — version, key epoch, random file nonce, file id (53 bytes)
    • chunk — nonce + AES-256-GCM of 64 KiB, bound to its index and "is last"
    • file id — also inside the encrypted name, so a swapped file is detected

    03 — Install

    Up and running in a minute

    Prebuilt binaries for macOS and Linux are on the releases page (pre-releases, with SHA-256 checksums). Or build from source with Rust 1.99.1 (pinned in rust-toolchain.toml).

    1. Install macFUSE (needs its kernel extension; on Apple Silicon allow it in the Startup Security Utility and in System Settings).

    brew install --cask macfuse

    2. Download aarch64-apple-darwin (Apple Silicon) or x86_64-apple-darwin (Intel) from the releases page, unpack it and put crypto-drive into your PATH. The binary is not signed: if you downloaded it with a browser, remove the quarantine flag once:

    xattr -d com.apple.quarantine crypto-drive

    Or build from source:

    git clone https://github.com/mkloubert/crypto-drive.git
    cd crypto-drive && cargo build --release

    macFUSE libraries in another place? Build with FUSE_LIB_DIR=<dir>.

    1. Install FUSE 3 (gives fusermount3):

    sudo apt install fuse3

    2. Download x86_64 or aarch64, -linux-gnu or -linux-musl (static) from the releases page, unpack it and put crypto-drive into your PATH. Or build from source:

    git clone https://github.com/mkloubert/crypto-drive.git
    cd crypto-drive && cargo build --release

    On Linux the drive talks to the kernel directly and needs no libfuse.

    Quick start 
    # create a vault: asks for a password, prints the recovery key
$ crypto-drive init ~/vault

# mount it (use the key file path that init printed)
$ mkdir ~/drive
$ crypto-drive mount ~/vault ~/drive \
    --key-file ~/.crypto-drive/keys/<time>_vault.cd-key

# ... work in ~/drive ...
$ crypto-drive unmount ~/drive
    Commands
    initCreate a vault. --pad-sizes hides exact file sizes.
    mountMount a vault as a drive. --daemon runs in the background.
    unmountUnmount a drive. --force for a busy drive.
    passwdChange the password. The master key stays the same. The vault must not be mounted.
    rotate-keyReplace the master key and re-encrypt the whole vault. Resumable.
    recovery-keyPrint the recovery key again.
    recoverWrite a new key file from the recovery key.
    checkCheck the whole vault. Exit 0 = fine, 1 = warnings, 2 = errors. Never writes.

    04 — Threat model

    Honest about the limits

    The attacker can read and change the vault: a cloud provider, a stolen disk, a backup. Here is what that attacker can and cannot do.

    ● protected

    • Contents of all files
    • Names of all files and directories
    • Changed, swapped, cut or mixed-in chunks from other files
    • Files or directories swapped with each other
    • Offline password attacks, while the key file is kept outside the vault

    ● visible

    • Rough file sizes (exact size hidden with --pad-sizes)
    • Number of files and directories
    • Tree shape and nesting depth
    • Timestamps and times of changes
    • Exact length of every name
    • Which file is which over time (file and directory ids stay the same across renames and key rotation)
    • Which 64 KiB parts of a file changed

    ● not protected

    • Malware or root on the running, unlocked system
    • Rollback of a single file to an older version
    • Deleted files, or deleted files brought back
    • Mixing old and new chunks of the same file
    • Moves between directories with a planted .cd-dir copy (logged and reported by check)
    • Copies of old ciphertext together with an old key

    Status

    crypto-drive is pre-release software. The on-disk format is frozen (version 1, with golden test vaults and known-answer tests), but there has been no external security audit yet. Keep backups of important data. A power cut during a write can make a 64 KiB part of a file unreadable, so databases and VM images are better kept outside the drive. On macOS the drive serves one request at a time and reports itself as case-insensitive (it is case sensitive). Not supported yet: symlinks, hard links, persistent extended attributes, a GUI and Windows.

    05 — Quality

    Tested like it matters

    The core has no FUSE dependency, so the whole file system logic runs in plain unit tests. A second, independent Python implementation produces the test vectors.

    Golden vaults
    Two frozen v1 vaults every future version must read.
    Tamper tests
    Every bit flip, swap or cut gives an error, never wrong bytes.
    Model tests
    Random operation lists against an in-memory model with proptest.
    Fuzzing
    Nine cargo-fuzz targets, from parsers to hostile vault trees.

    Lock it. Sync it. Forget it.
