# One Directory Id per Directory – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every reader decrypts the names of a directory only with the id
in its canonical `.cd-dir`; ids of `.cd-dir` copies are never used
(review SEC-5).

**Architecture:** `read_dir_ids` becomes `read_dir_id` returning
`DirIds { id, foreign_copy }`. The drive, `check`, `rotate-key` and the
vault walks take one `DirId`. A copy with another id gives a warning in
the drive and the error finding `foreign-dir-id` in `check`.

**Tech Stack:** Rust 2024; crates `crypto-drive-core` (`fs/dirstate.rs`,
`fs/listing.rs`, `fs/mod.rs`, `check.rs`, `rotate.rs`, `vault.rs`) and
`crypto-drive` (`cmd/check.rs`).

**Spec:** `docs/superpowers/specs/2026-11-08-one-dir-id-design.md`

## Global Constraints

- No change of the on-disk format; golden vaults and KATs untouched.
- `MAX_DIR_ID_COPIES` = 16: at most this many copies are read, in name
  order; reading stops at the first copy with another id.
- Copy = name starts with `.cd-dir`, is not `.cd-dir` or `.cd-dir.tmp`,
  regular file of exactly 16 bytes (as today).
- Drive warning text exactly:
  `a .cd-dir copy in {real} holds another directory id; entries named under it are not shown. Run crypto-drive check (foreign-dir-id).`
  (`{real}` = real entry name of the directory; `/` for the root is not
  possible, the root has no copies.)
- New `FindingKind::ForeignDirId`, `Severity::Error`, CLI text
  `foreign-dir-id`.
- Simple English; AGPL headers; git read-only for Claude ("commit" = propose
  a message).
- Commands need `export PATH="$HOME/.cargo/bin:$PATH";` first.

## Review Focus

1. A planted copy with another id in a directory that also has a
   same-id copy: warning once, entries under the foreign id hidden
   (covered: Task 1 test `entries_under_foreign_dir_id_copy_are_hidden`
   adds a same-id copy too).
2. Thousands of planted copies: listing cost stays bounded (covered: Task 1
   test `many_dir_id_copies_are_cheap` checks `read_dir_id` reads at most
   16 and the listing works).
3. A long entry (`.cd-cdl`) moved with a planted copy: hidden in the drive;
   `rotate-key` stops with the hidden-data error naming it (covered:
   Task 3 test `rotation_stops_on_long_entry_under_foreign_dir_id`).
4. `recover` / `rotation_unfinished` with a planted entry: behaves like a
   planted junk name today (no new test; existing recover tests stay green).
5. `check` exit code with only same-id copies stays 1 (covered: Task 2
   `same_id_copy_is_a_warning`).

```
fix(fs): use only the canonical .cd-dir id in every reader

Readers tried the ids of up to 15 .cd-dir copies, so entries moved
between directories with a planted copy showed up without an error,
and rotate-key made such a move permanent (review SEC-5). A copy with
another id has no legitimate source in format v1. Now only the
canonical id is used: such entries are hidden, the drive warns once
per mount and check reports foreign-dir-id as an error. Listings try
one id instead of up to 16.
```
